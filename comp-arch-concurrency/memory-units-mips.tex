\section{Memory Units and Introduction to MIPS}

\subsection{Memory Units}
A binary digit (a bit) is a single $0/1$ digit. A byte (nowadays) is a unit of $8$ bytes, and a kilobyte (KB) is
$2^{10}=1024$ bytes, a megabyte $2^{20}=1024$ KB, then GB, TB, PB, EB, and so on.

\subsection{Working unit size -- Words}
A word is a natural unit of data used by a given processor. In this course MIPS32 is used, but MIPS16 and MIPS64 do exist.
This typically indicates the sizes of registers, memory addresses, instruction sizes, and floating point variable sizes.

\subsection{MIPS Registers}
The MIPS32 CPU has 32 registers: $\$0, \dots, \$31$, each of size 32 bits. Different registers serve different purposes;
for example, \$0 always contains the value 0. Unlike x86 and other complex instruction set architectures (ISAs), MIPS only 
operates on registers. This simplifies the ISA, but increases the number of instructions. \\
For example: \texttt{Mem[0x1001000] += Mem[0x1001004]} translates to:
\begin{itemize}
    \item Read \texttt{Mem[0x1001000]} into register.
    \item Read \texttt{Mem[0x1001004]} into register.
    \item Compute the sum of both registers.
    \item Write the result back to \texttt{Mem[0x1001000]}.
\end{itemize}
Having simpler instructions means we can have fewer of them. With MIPS, we have the first 6 bits as the opcode, and the
next 26 bits as the argument:

\subsection{Instruction Types}
In MIPS32, both addresses and instructions are 32-bit long. For instructions, 6 out of the 32 bits are used for opcodes.
Therefore, we need to be able to encode addresses to be able to jump locations or load array addresses into pointers, and
set 32-bit values into registers. We have three instruction types: 
\begin{enumerate}
    \item \textbf{R}-ithmetic (between register) operations, such as \texttt{add \$8, \$1, \$2} and
\texttt{sub \$12, \$6, \$3};
    \item \textbf{I}-mmediate (including fixed numbers) operations, like \texttt{addi \$15, \$15, -1}
and \texttt{beq \$10, \$14, 0x00000002};
    \item \textbf{J}-ump operations including \texttt{j 0x004000050} and \texttt{jal 0x00400007c}
\end{enumerate}
The MIPS Reference Card is on the course Moodle website.

\subsection{Shift Instructions}
\begin{center}
\texttt{srl \$11, \$7, 4} \qquad \texttt{0x00075842} \qquad R[rd] = R[rt] $\gg$ shamt \quad (rs is 0)

\vspace{1ex}
$\underbrace{\texttt{000000}}_{\mbox{opcode}}\,
 \underbrace{\texttt{00000}}_{\mbox{rs = 0}}\,
 \underbrace{\texttt{00111}}_{\mbox{rt = \$7}}\,
 \underbrace{\texttt{01011}}_{\mbox{rd = \$11}}\,
 \underbrace{\texttt{00100}}_{\mbox{shamt = 4}}\,
 \underbrace{\texttt{000010}}_{\mbox{funct = 02}_{\rm hex}}$
\end{center}

\[
\begin{array}{rcl@{\qquad}rcl}
100_{10} \ll 4 & = & 100 \cdot 2^4 = 1600
  & 1100100_2 \ll 4 & = & 1100100\underline{0000}_2 \\[1ex]
100_{10} \gg 4 & = & \left\lfloor \frac{100}{2^4} \right\rfloor = 6
  & 1100100_2 \gg 4 & = & 110_2
\end{array}
\]

\noindent $-100_{10} \gg 4 = {?}$ \quad It depends on the kind of shift:
\[
\begin{array}{l@{\quad}l}
\mbox{Logical:} & \texttt{0xffffff9c >>> 4} = \texttt{0x0ffffff9} = 268435449_{10} \\[1ex]
\mbox{Arithmetic:} & \texttt{0xffffff9c >> 4} = \texttt{0xfffffff9}
  = \left\lfloor \frac{-100}{2^4} \right\rfloor = -7
\end{array}
\]

\subsection{Pseudo Instructions}
There also exists \textit{pseudo} instructions that are not real MIPS32 instructions (i.e. they do not have opcodes and
aren't recognised by the CPU), but they can be translated into real instructions by the assembler. For example, \texttt{
move \$8, \$9} can be translated into \texttt{add \$8, \$9, \$0}.

\subsection{High-level Commands}
Going one way, we have the \textbf{disassembly} of machine code to assembly code and \textbf{reverse engineering} of
assembly code to high level code like \texttt{x = a - b + c - d;}. In contrast, going from a high level language to 
assembly is \textbf{not unique}. There are multiple heuristics for optimisation, but going from assembly to machine code
\textbf{is} unique.
